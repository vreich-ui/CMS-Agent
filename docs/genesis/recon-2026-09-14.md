## 2. Divergence list — `genesis-lab-2` vs `dr-lurie`

Each row names the mechanism, not the tenant.

### D1 — no `objectDialect` on a minted record (F2)
**LOCAL.** `projectCreateSchema` has no `objectDialect` key and `createProject` never copies one; `runSiteGenesis`'s `createProject(...)` call does not pass one. `objectDialect` is reachable **only** through `project.update` (`objectDialectPatchSchema` + `mergeObjectDialect`, which requires `siteObjectId` + `taxonomyRegistryObjectId` + `objectIdSource` together). So every genesis-minted tenant is born dialect-less, and every site-scoped artifact bridge verb refuses with `artifact_site_scope_missing`.

`dr-lurie` has one only because it is a **code-defined** project (`DR_LURIE_OBJECT_DIALECT`):

```
siteObjectId: "site_drlurie"
taxonomyRegistryObjectId: "tax_drlurie"
objectIdSource: "request_id"
requestIdPattern: "^req_[a-z0-9_]+_\\d{8}_\\d{2}$"
defaultObjectType: "content_item"
voiceObjectId: "voice_drlurie"
```
(no `strategyObjectId` — it resolves by convention.)

### D2 — **the two repos derive tenant object ids differently** (new; not in the brief)
**LOCAL, both repos.**

| | derivation | `genesis-lab-2` → | `dr-lurie` → |
|---|---|---|---|
| cms-agent `conventionalTenantSlug` (`projectTypes.ts`) | `toLowerCase().replace(/[^a-z0-9]/g,"")` | `genesislab2` | `drlurie` |
| platform `idsFor` (`create-site.mjs`) | `clientSlug.replace(/-/g,'_')` | `genesis_lab_2` | n/a (slug is `drlurie`) |
| cms-agent `visualStandardIds.sanitizeIdSegment` | `replace(/[^a-z0-9]+/g,"_")` | `genesis_lab_2` | `drlurie` |
| cms-agent `siteGenesis.houseVisualStandardId` | `slug.replace(/-/g,"")` | `genesislab2` | `drlurie` |

Three spellings of one rule. They agree for every hyphen-free slug — which is every tenant that exists today except `genesis-lab-2` — and disagree for every hyphenated one. Ground truth is what the scaffold actually wrote: `sites/genesis-lab-2/config/site-identity.ts` declares `siteId: 'site_genesis_lab_2'`.

Consequences on a hyphenated minted tenant: `conventionalStrategyObjectId` addresses `strat_genesislab2`, which does not exist; `houseVisualStandardId` plans `vis_genesislab2` against a scaffold that minted `vis_genesis_lab_2`.

**Resolution taken (G2):** genesis writes the dialect explicitly, from a single helper that mirrors the scaffold's own derivation, and the record pointer then outranks the convention everywhere (`getEditorialStrategy` reads the pointer first; `voicePrefetch` reads only the dialect). Neither `conventionalTenantSlug` nor the scaffold's convention is changed — changing either would rename live objects for an existing tenant.

### D3 — the tenant's object store has no credential (F3)
**LOCAL.** The F3 string is `invokeObjectStore`'s missing-`PUBLISH_SECRET` branch. `PUBLISH_SECRET` is `cls: 'per-site', generate: randomSecret(32)` in `ENV_CHECKLIST` and is pushed **only** by `create-site.mjs --provision-only`. `runSiteGenesis` reaches that branch only under `mode === "live" && platformRoot`; with no `PLATFORM_REPO_ROOT` mounted (the Cloud Run deployment's normal state) it falls to `netlify.createSite(...)`, which mints the site and nothing else. The five auto-mintable/derivable per-site values are then never written:

`PUBLISH_SECRET`, `MCP_HTTP_AUTH_TOKEN`*, `ARTIFACT_UPLOAD_TOKEN_SECRET`, `TRACKING_SALT`, `NETLIFY_SITE_ID`.

\* `MCP_HTTP_AUTH_TOKEN` is the exception — the `tenant_mcp_token_custody` block already mints it, installs it and stores it in Secret Manager as `<slug>-mcp-token`, registering `tokenSecretRef` on the record.

**Correction to the brief:** the Sep-9 `<SLUG>_MCP_TOKEN` custody gap is therefore **already closed in code**; it is not the same env family as the object-store credential, and G3 has nothing to close there.

### D4 — no committed aggression ceiling on a minted tenant (F4, `no_ceiling`)
**LOCAL.** The engine's ceiling comes from the tenant's `object_contract(content_item)` response (`contractReduction.extractAggressionCeiling` → `ReducedContract.aggressionCeiling` → `resolveAggressionVector`), which platform answers from `getSiteIdentity().aggressionCeiling` — i.e. the committed `sites/<slug>/config/site-identity.ts`. `siteIdentityTemplate` in `create-site.mjs` emits seven fields and **not** `aggressionCeiling`; `sites/drlurie/config/site-identity.ts` l. 49 does. So a minted tenant fails platform's own `aggression_ceiling_declared` check and the engine stamps `resolved_vector_unclamped:no_ceiling`.

The voice skeleton is **not** the source of the ceiling; G4's placement of it there is a misattribution.

### D5 — F4's remaining warnings are downstream of D1 and D3
**LOCAL reasoning over EXTERNAL-UNVERIFIED evidence.**
- `voice_prefetch_fallback:voice_object_unconfigured` — `voicePrefetch` returns this code on exactly one condition: no `objectDialect.voiceObjectId` **and** a fallback present. The minted record has the genesis `editorialVoiceFallback` and no dialect. Pure D1.
- `contract_prefetch_failed:prefetch_object_type_unresolved` — `contractPrefetch` cannot resolve an object type with no `objectDialect.defaultObjectType`. Pure D1.
- `site_prefetch_withheld:contract_prefetch_failed` — declared downstream of the above.
- `strategy_prefetch_fallback:strategy_object_invalid` — the read is attempted at `strat_genesislab2` (D2) against a tenant whose object store answers the D3 tool error; the payload extractor then fails the body-shape check. D2 + D3.

### D6 — `autonomyMode` is never set at mint (F5)
**LOCAL.** `createProject` hard-writes `publishingPolicy: { ...DEFAULT_PUBLISHING_POLICY }`, which declares `publishEnabled`/`requiresExplicitPublish`/`description` and **no** `autonomyMode`; `executor.capturePublishingPolicySnapshot` resolves an absent mode to `"operator-gated"`. `autonomyMode` is reachable only through `project.update`'s single-field crack — which is how `dr-lurie` came to be `"autonomous"` on 2026-09-07 (`readinessContentChecks.ts` l. 238 records the date). `drLurie/definition.ts`'s own `publishingPolicy` block also does not declare it, confirming it was set on the record, by hand, after the fact.

### D6a — the reference tenant's own autonomy is a LIVE-RECORD fact its code definition does not declare
**LOCAL. Found while building the parity check; deliberately NOT fixed in this track.**

`drLurieProjectConfig.publishingPolicy` declares `publishEnabled`, `requiresExplicitPublish` and
`description` — and no `autonomyMode`. The live record has been `"autonomous"` since 2026-09-07.
`migrateDefaultProjectConfig` **replaces a code project's whole record** the moment its
`definitionVersion` moves (`defaultMigration.ts` l. 26–30: `return { config: clone(defaultConfig),
changed: true }`). So the next version bump on dr-lurie or platform silently reverts that operator
decision to `operator-gated`, and every run on the fleet's two oldest tenants starts parking at
`publication_controller` with nothing naming why.

The fix is one line per definition. It is not in this patch: declaring it re-baselines **24 tests
across 8 files** in this repo, all of which pin "no declared autonomy" as the engine's default
(`publishGateVisibility`, `approvalGateStateMachine`, `deterministicPublishExecutor`,
`workflowRunnerConcurrency`, `runConductorJob`, `workflowLateStageEntrypoint`,
`workflowRunnerTools`, `improvementEngine`). That is a fleet-wide behaviour decision, not a side
effect of genesis parity. `genesisParity.test.ts` asserts the CURRENT state, so the day somebody
declares it the test says so out loud instead of silently agreeing.

### D6b — a fourth spelling of the tenant slug, this one harmless
**LOCAL.** Genesis writes `tracking.projectId = slug` (hyphens intact: `genesis-lab-3`) and the
site's own `TRACKING_PROJECT_ID` to the same value, while `resolveTrackingPartition`'s *fallback*
derives `genesislab3` and platform's `siteShortId` would give `genesis_lab_3`. Not a defect: the
recorded value outranks the convention on the CMS-Agent side and the env var outranks the site's own
fallback on the platform side, so both ends read the same partition. Recorded here because it is a
fourth spelling of one idea in a file full of consequences of exactly that, and because the parity
check deliberately does **not** flag a recorded partition that differs from the convention — an
override is the field's whole purpose.

### D7 — `publishableTypes` is **not** a project-level divergence
**LOCAL.** `resolvePublishableTypeCharter(run.workflowId)` is the only source. `publishing_conductor` → `["page","navigation"]` for **every** project, `dr-lurie` included. It gates `buildObjectPublishPlan`'s recipe set and `assertRecipeAuthorshipAllowed`, both of which no-op for a non-recipe `objectType`; the content_item publish path (`publishPayload.ts` / `publisher.publishRun`) publishes under the project's own dialect type and is untouched by it. F5's snapshot reading is correct and means nothing about parity.

**Correction to the brief:** G5's "make genesis emit drlurie's set" has no referent, and widening the charter is forbidden by the standing publish-charter rule. The parity check deliberately does not compare `publishableTypes`.

### D8 — `defaultToolPolicy` / `toolPolicies` are already at parity
**LOCAL.** `genesisTenantProfile()` is spread into `createProject` at mint: `definitionVersion: 2`, `defaultToolPolicy: "blocked"`, the 39-verb map. F5's "`defaultToolPolicy: blocked` with an explicit allowlist" is therefore the *intended* state, not a divergence. What G5 must still verify is that the map covers drlurie's **effective** publish set; `site_apply_brand_imagery` is a recorded, deliberate withholding (`GENESIS_WITHHELD_ROUTE_VERBS`).

### D9 — `tracking.projectId` and `clientSiteBinding` are already written at mint
**LOCAL.** `createProject` receives `tracking: { projectId: slug }` (bare slug) and `clientSiteBinding: { netlifySiteName, netlifySiteId }`. Both already satisfy G5's requirement; the parity check asserts them rather than the code adding them.

### D10 — `sourceUrl` is structurally required (G1)
**LOCAL.** `duplicateInput.sourceUrl` is non-optional; the handler does `new URL(input.sourceUrl).origin` inside `runSiteGenesis` to seed `capturePolicy.allowedCrawlOrigins`, and always starts a `capture_conductor` run. A mint therefore cannot happen without naming a site to crawl, and always burns a capture run.
